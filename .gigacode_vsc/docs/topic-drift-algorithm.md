# Алгоритм дрейфа тем (Topic Drift)

## Архитектура

Система использует **трёхэтапный пайплайн**:

---

## Этап 1: Кластеризация (analyzer.py)

Для каждой недели (текущей и предыдущей):

1. **Загрузка эмбеддингов** из Parquet-файлов → матрица `(n_samples, dim)`
2. **Стандартизация** через `StandardScaler` (ноль mean, единичная дисперсия)
3. **UMAP** — нелинейное снижение размерности с `dim` (768) до `UMAP_N_COMPONENTS` (по умолчанию **5**)
4. **HDBSCAN** — кластеризация по плотности, `min_cluster_size=5`, шум = `-1`

> **Итого:** кластеризация используется, но **не для дрейфа** — только для группировки статей и извлечения тем.

---

## Этап 2: Расчёт drift_score (analyzer.py, `compute_drift_score`)

**Основной алгоритм: усреднённое по измерениям одномерное расстояние Вассерштейна (1D EMD).**

### Формула

```
drift_score = (1 / D) × Σ W₁(P_d_old, P_d_new)
              d=1..D
```

Где:
- `D` — размерность эмбеддинга (например, 768)
- `P_d_old` / `P_d_new` — эмпирическое распределение значений в измерении `d` для прошлой / текущей недели
- `W₁` — 1D Wasserstein Distance из `scipy.stats.wasserstein_distance`

### Ключевые особенности

| Характеристика | Значение |
|---|---|
| Расстояние | Wasserstein (Earth Mover's Distance) |
| Размерность | **По-измерению (1D)**, не многомерное EMD |
| Библиотека | `scipy.stats.wasserstein_distance` |
| Нормализация | **Отсутствует** — значение не ограничено `[0, 1]` |
| Диапазон | Зависит от масштаба эмбеддингов |

### Код

```python
def compute_drift_score(embeddings_old, embeddings_new) -> float:
    dim = embeddings_old.shape[1]
    distances = []
    for d in range(dim):
        dist = wasserstein_distance(embeddings_old[:, d], embeddings_new[:, d])
        distances.append(dist)
    return np.mean(distances)
```

## Этап 3: Определение сдвинутых тем (analyzer.py, `detect_shifted_topics`)

**Алгоритм: позиционное сравнение кластеров (very naive).**

1. Кластеры сравниваются по **индексу в словаре**
2. Для каждого кластера извлекаются топ-N терминов через `collections.Counter`
3. Если список терминов отличается — тема помечена как «сдвинувшаяся»

```python
for i in range(min(len(prev_items), len(cur_items))):
    if prev_terms != cur_terms:
        shifted.append({"old_terms": prev_terms, "new_terms": cur_terms})
```

> Это **не** сравнение центроидов и не matching по similarity — просто посимвольное сравнение списков слов по порядку.

### Извлечение терминов

1. Все тексты кластера → `re.findall(r'\b\w+\b', text.lower())`
2. `collections.Counter` → частотный словарь
3. Удаление стоп-слов (хардкод для русского)
4. Топ-N слов

## Известные ограничения (из README backlog)

1. **Нет нормализации drift_score** — docstring говорит `0..1`, но код возвращает raw mean EMD
2. **Per-dimension EMD** вместо истинного многомерного
3. **Дрifting topics** — сравнение по индексу словаря, а не по центроидам
4. **drift.py пустой** — выделенный модуль так и не реализован (0 строк)
5. **Визуализация кластеров** — stub, т.к. analyzer не возвращает UMAP-координаты
