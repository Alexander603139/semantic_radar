# Embedder — сервис векторизации текстов

Сервис принимает по REST массив статей, разбивает текст на перекрывающиеся чанки, **динамически выбирает модель эмбеддингов из реестра в `storage`**, вычисляет векторы, сохраняет результат в Parquet-файл и передаёт его в `storage`. Поддерживает локальные модели (через `sentence-transformers`) и облачные модели через OpenAI-совместимый API (Яндекс через Timeweb AI Gateway).

> **Важно:** начиная с фичи «Мульти-модельность» (Этапы 3–8), сервис больше не использует фиксированную модель `all-MiniLM-L6-v2`. Активная модель определяется из настроек пользователя в `storage` или передаётся явно через параметр `model_slug`. При сбое облачного API автоматически срабатывает **fallback** на локальную модель `intfloat/multilingual-e5-base`.

## Архитектура стратегий

Сервис использует паттерн «Стратегия» для векторизации:

- **`BaseEmbedder`** — абстрактный базовый класс с методом `embed_texts(texts, requires_prefix, prefix_type)`.
- **`LocalHuggingFaceEmbedder`** — для локальных моделей (`intfloat/multilingual-e5-base`, `all-MiniLM-L6-v2`). Загружает модель по пути из реестра, поддерживает префиксы `passage:` / `query:`.
- **`OpenAIAPIEmbedder`** — для облачных моделей через OpenAI-совместимый API (Яндекс через Timeweb). Включает обработку лимитов (429), серверных ошибок (5xx), экспоненциальную задержку (1с → 2с → 4с) и параллельный батчинг с ограничением конкурентности.
- **`EmbedderFactory`** — фабрика, которая по конфигурации модели из реестра возвращает нужный экземпляр стратегии. Кэширует локальные модели в памяти, чтобы не загружать их повторно.

## Установка и запуск локально

### Требования

- Python 3.11+
- Запущенный сервис `storage` (для получения реестра моделей и сохранения векторов)
- Для локальных моделей: веса моделей в папке `models/` (или путь, указанный в реестре)

### Шаги

1. Клонировать репозиторий.
2. Создать виртуальное окружение и активировать:
   ```bash
   python -m venv venv
   source venv/bin/activate  # или venv\Scripts\activate для Windows
   ```
3. Установить зависимости:
   ```bash
   pip install -r services/embedder/requirements.txt
   ```
4. Запустить сервис:
   ```bash
   python -m services.embedder.src.main
   ```

По умолчанию сервер запускается на порту **8002**.

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `STORAGE_URL` | URL сервиса `storage` (для реестра моделей и сохранения векторов) | `http://storage:8007` |
| `YA_AI_PROXY_KEY` | API-ключ для Яндекса через Timeweb AI Gateway | (пусто) |
| `YA_BASE_URL` | Базовый URL для Яндекс API (альтернативный) | (пусто) |
| `CHUNK_SIZE` | Максимальное количество слов в чанке | `256` |
| `CHUNK_OVERLAP` | Перекрытие между чанками (в словах) | `32` |
| `PORT` | Порт для FastAPI | `8002` |

> **Устаревшие переменные:** `MODEL_NAME` и `VECTORS_ROOT` больше не используются. Модель выбирается динамически из реестра в `storage`, а векторы отправляются в `storage` через API.

## API

### POST /embed

Принимает массив статей, вычисляет эмбеддинги для каждого чанка и сохраняет результат в `storage`.

**Запрос:**
```json
{
  "user_id": "admin",
  "model_slug": "e5-base-local",
  "articles": [
    {
      "id": "article_123",
      "title": "Заголовок статьи",
      "text": "Полный текст статьи...",
      "source": "lenta.ru",
      "published_at": "2026-07-24T00:00:00"
    }
  ]
}
```

> **Примечание:** параметр `model_slug` опционален. Если он не передан, используется активная модель пользователя из настроек `storage`. Если передан — используется указанная модель (для ручной проверки или специфичных задач).

**Ответ:**
```json
{
  "status": "ok",
  "vectors_file": "uuid-файла-в-storage",
  "chunk_count": 456
}
```

### GET /health

Проверка работоспособности сервиса.

## Логика работы

1. **Чанкинг** — текст каждой статьи разбивается на перекрывающиеся чанки (по умолчанию 256 слов, перекрытие 32 слова).
2. **Выбор модели** — если в запросе передан `model_slug`, используется указанная модель из реестра. Иначе — активная модель пользователя (`active_model_slug` из настроек `storage`).
3. **Инициализация стратегии** — `EmbedderFactory` создаёт нужный экземпляр стратегии. Локальные модели кэшируются в памяти.
4. **Векторизация** — стратегия вычисляет эмбеддинги. Для моделей типа E5 применяются префиксы `passage:` (для статей) или `query:` (для запросов).
5. **Обработка ошибок** — если облачный API падает (401, 500, 429, таймаут), сервис автоматически переключается на локальную модель `e5-base-local` и записывает событие **fallback** в `storage` (Этап 7).
6. **Формирование Parquet** — из чанков и эмбеддингов формируется DataFrame, который сериализуется в Parquet.
7. **Отправка в `storage`** — Parquet-файл загружается в `storage` через API. В метаданных указываются `chunk_count`, `source_count`, `model_slug` и `model_name`. В `storage` файл сохраняется в папке, соответствующей модели (например, `admin/vectors/e5-base-local/2026-09-15.parquet`) — это обеспечивает изоляцию векторов разных моделей (Этап 8).

## Интеграция с другими сервисами

- **`ingestor`** — вызывает `/embed` после парсинга статей.
- **`storage`** — источник реестра моделей и место хранения векторов. `embedder` запрашивает активную модель через `GET /settings/{user_id}` и список моделей через `GET /ai-models`, а сохраняет векторы через `POST /upload`.
- **`analyzer`** — получает векторы из `storage` (не напрямую из `embedder`).

## Fallback-логика (Этап 7)

Если активная модель — облачная (Яндекс), но:
- отсутствует `YA_AI_PROXY_KEY`,
- API возвращает ошибку 401/500/429,
- происходит таймаут или сетевой сбой,

сервис автоматически переключается на локальную модель `e5-base-local`. Событие fallback записывается в `storage` в поле `last_fallback_event` таблицы `user_settings` и отображается в админ-панели.

## Особенности реализации

- **Поддержка префиксов** — для моделей типа E5 (`intfloat/multilingual-e5-base`) к текстам добавляется префикс `passage:` или `query:` в зависимости от задачи. Это критично для качества эмбеддингов таких моделей.
- **Ретраи для API** — при временных ошибках (429, 500–504) запрос повторяется до 3 раз с экспоненциальной задержкой (1с, 2с, 4с). Для ошибок 400/401 повтор бессмысленен — сервис сразу переходит к обработке ошибки.
- **Параллельный батчинг** — для API-моделей запросы отправляются параллельно, но с ограничением конкурентности (по умолчанию 3 одновременных запроса), чтобы не упереться в лимиты.
- **Кэширование моделей** — локальные модели загружаются в память один раз и переиспользуются между запросами.

## Беклог (дальнейшие улучшения)

### Производительность

- Поддержка пакетной обработки для локальных моделей (батчи по 32–64 текста).
- Горизонтальное масштабирование: несколько экземпляров `embedder` для параллельной обработки.

### Архитектура

- Переход на асинхронную очередь (Redis / RabbitMQ) вместо синхронного REST-вызова от `ingestor`.
- Кэширование эмбеддингов для повторяющихся текстов.

### Безопасность

- Добавить JWT-авторизацию (проверка токена через `user_manager`).

### Модели

- Поддержка других моделей эмбеддингов (например, `intfloat/multilingual-e5-large`, `bge-m3`).
- Оптимизация чанкинга с учётом семантических границ (предложения, абзацы).

## Используемые технологии

- **FastAPI** — веб-фреймворк
- **sentence-transformers** — библиотека для локальных моделей эмбеддингов
- **PyTorch** — бэкенд для локальных моделей
- **openai** — Python-клиент для OpenAI-совместимого API (Яндекс через Timeweb)
- **httpx** — асинхронные HTTP-запросы к `storage`
- **PyArrow / Pandas** — работа с Parquet-файлами
- **Pydantic** — валидация данных
- **pydantic-settings** — конфигурация через переменные окружения
