# Ingestor — сервис сбора и очистки новостных статей

Сервис отвечает за первый слой архитектуры: парсинг новостных сайтов, извлечение основного текста, заголовка, даты публикации и сохранение в структурированном виде. Работает асинхронно, использует `httpx` для статичных страниц и `playwright` для динамических (с JavaScript), извлекает контент с помощью `readability-lxml` и `trafilatura`.

> **Важно:** после успешного парсинга сервис **реально** вызывает `embedder` для векторизации статей, а затем автоматически запускает `analyzer` и `reporter` для генерации аналитического отчёта. Поведение вызова `embedder` регулируется переменной окружения `EMBEDDER_MOCK`.

## Установка и запуск локально

### Требования

- Python 3.11+
- Установленный браузер Chromium для Playwright
- Запущенный сервис `storage` (для хранения статей, списка сайтов, расписания и настроек пользователя)
- Запущенный сервис `embedder` (для векторизации статей)

### Шаги

1. Клонировать репозиторий.
2. Создать виртуальное окружение и активировать:
   ```bash
   python -m venv venv
   source venv/bin/activate  # или venv\Scripts\activate для Windows
   ```
3. Установить зависимости:
   ```bash
   pip install -r services/ingestor/requirements.txt
   ```
4. Установить браузер Playwright:
   ```bash
   playwright install chromium
   ```
5. Запустить сервис:
   ```bash
   python -m services.ingestor.src.main
   ```

По умолчанию сервер запускается на порту **8001**.

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `INGESTOR_PORT` | Порт для FastAPI | `8001` |
| `EMBEDDER_URL` | URL для вызова `embedder` | `http://embedder:8002/embed` |
| `EMBEDDER_MOCK` | Если `True`, вызов `embedder` заменяется заглушкой (используется в проекте для управления поведением) | `True` |
| `SCHEDULE_CRON` | Cron-строка по умолчанию (реальное расписание хранится в `storage`) | `0 5 * * *` |
| `OUTPUT_DIR` | Папка для локального сохранения статей (используется как `fallback` при недоступности `storage`) | `./data/articles` |
| `STORAGE_URL` | URL сервиса `storage` | `http://storage:8007` |

> **Примечание:** переменная `EMBEDDER_MOCK` активно используется в проекте. Если она установлена в `True`, вызов `embedder` заглушается (логируется, но реальный запрос не отправляется). Если `False` — вызов выполняется реально. На продакшене, судя по логам работы, вызов выполняется реально, что означает, что `EMBEDDER_MOCK` установлен в `False` в файле `.env` (или переменная не задана и используется значение из `.env` через `pydantic-settings`).

## API

### POST /run

Запускает парсинг для переданного списка сайтов. Возвращает `task_id` для отслеживания статуса.

**Запрос:**
```json
{
  "user_id": "admin",
  "sources": ["https://lenta.ru", "https://ria.ru"],
  "limit": 5
}
```

> **Примечание:** если `sources` не передан, используется список сайтов из настроек пользователя в `storage` (`user_settings.sources`).

**Ответ:**
```json
{
  "task_id": "uuid",
  "status": "started",
  "message": "Задача поставлена в очередь"
}
```

### GET /status/{task_id}

Возвращает статус выполнения задачи.

**Ответ:**
```json
{
  "task_id": "uuid",
  "status": "completed",
  "result": {
    "total_articles": 10,
    "sources_processed": 2
  },
  "error": null
}
```

Возможные значения `status`: `pending`, `running`, `completed`, `failed`.

### GET /admin/settings

Возвращает настройки пользователя (`admin`): список сайтов, расписание, часовой пояс, активную модель, контекст и порог.

**Ответ:**
```json
{
  "sources": ["https://nn.rbc.ru/", "https://news.mail.ru/"],
  "schedule_cron": "0 5 * * *",
  "timezone": "UTC",
  "active_model_slug": "e5-base-local",
  "context": null,
  "threshold": 0.6
}
```

### POST /admin/settings

Обновляет настройки пользователя (`admin`): список сайтов, расписание, часовой пояс. После обновления **перезапускает планировщик** с новыми параметрами.

**Запрос:**
```json
{
  "sources": ["https://lenta.ru", "https://ria.ru"],
  "schedule_cron": "0 5 * * *",
  "timezone": "UTC"
}
```

### GET /health

Проверка работоспособности сервиса.

## Планировщик

При старте приложения автоматически запускается встроенный планировщик (на базе **APScheduler**), который выполняет задачу по расписанию, заданному в настройках пользователя (`user_settings.schedule_cron` в `storage`). Список сайтов также берётся из настроек пользователя (`user_settings.sources`).

Планировщик поддерживает:
- **Часовой пояс** (`timezone`) — расписание интерпретируется в указанном часовом поясе.
- **Перезапуск** — при обновлении настроек через `POST /admin/settings` планировщик автоматически перезапускается с новыми параметрами (функция `restart_scheduler`).

## Интеграция с другими сервисами

### `storage`

- **Сохранение статей** — после парсинга статьи сохраняются в `storage` через `POST /upload` (тип `articles`). Если `storage` недоступен, статьи сохраняются локально в папку `OUTPUT_DIR` (fallback).
- **Настройки пользователя** — список сайтов, расписание, часовой пояс, активная модель, контекст и порог хранятся в `storage` (таблица `user_settings`).

### `embedder`

- После сохранения статей `ingestor` вызывает `embedder` через `embedder_client` для векторизации текстов.
- Поведение регулируется переменной `EMBEDDER_MOCK`:
  - Если `True` — вызов заглушается (логируется, но реальный запрос не отправляется).
  - Если `False` — вызов выполняется реально через `httpx`.
- `ingestor` передаёт `user_id` и массив статей, но **не указывает модель** — выбор модели происходит на стороне `embedder` на основе активной модели пользователя в `storage`. Это позволяет менять модель эмбеддингов без изменения `ingestor`.

### `analyzer` и `reporter`

- После успешного парсинга и вызова `embedder` сервис **автоматически** запускает:
  1. `analyzer` (`POST /analyze`) для вычисления кластеризации и дрифта.
  2. `reporter` (`POST /generate`) для генерации HTML-отчёта.
- Если анализ или генерация отчёта падают, задача парсинга **не прерывается** (ошибка логируется, но задача завершается как `completed`).

## Беклог (дальнейшие улучшения)

### Алгоритм сбора ссылок (`get_article_links_from_html`)

- Улучшить эвристики для динамических сайтов: использовать `wait_for_selector` для контейнера ссылок, анализировать структуру страницы.
- Добавить поддержку `sitemap.xml` как альтернативного источника ссылок.
- Реализовать адаптивную фильтрацию ссылок (по наличию даты, ID, паттернам `/news/`, `/story/` и т.д.) без жёстких исключений.

### Масштабирование и отказоустойчивость

- Перейти на очередь задач (например, Redis + RQ или Celery) для распределения парсинга.
- Добавить повторные попытки с экспоненциальной задержкой для проблемных сайтов.
- Внедрить мониторинг (метрики в Prometheus) и алертинг.

### Поддержка пользователей

- Интеграция с `user_manager`: получение списка сайтов и лимитов по `user_id` для нескольких пользователей.
- Поддержка расписания для каждого пользователя (хранение в БД, чтение при старте планировщика).
- Добавить эндпоинт `/admin/run` с расширенными возможностями для администратора.

### Оптимизация

- Кеширование результатов парсинга (чтобы не перепарсить одну и ту же статью повторно).
- Асинхронная запись на диск (сейчас синхронная).
- Уменьшение дублирования кода между `fetch_html_httpx` и `fetch_html_playwright`.

### Безопасность

- Добавить авторизацию через JWT (проверка токена через `user_manager`).
- Ограничение количества запросов (rate limiting) для защиты от перегрузки.

## Используемые технологии

- **FastAPI** — веб-фреймворк
- **httpx** — асинхронный HTTP-клиент
- **Playwright** — управление браузером для рендеринга JavaScript
- **readability-lxml / trafilatura** — извлечение основного контента из HTML
- **Pydantic** — валидация данных
- **APScheduler** — планировщик задач
- **pytz** — работа с часовыми поясами
