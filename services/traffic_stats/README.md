# Traffic Stats — сервис измерения трафика доменов

Сервис принимает список доменов (например, из списка сайтов пользователя), нормализует их и запрашивает статистику авторитетности у внешнего API **OpenPageRank** (от проекта Keywords Everywhere). Возвращает для каждого домена показатели `open_page_rank`, `rank` и `referring_domains`. Используется в админ-панели (кнопка «📊 Измерить» в блоке «Управление списком сайтов») для оценки качества источников парсинга.

> **Важно:** сервис работает в режиме **MVP**. Сохранение результатов во внутренний `storage` пока заглушено (только логирование), а эндпоинт получения задачи по `task_id` не реализован (возвращает 501).

## Установка и запуск локально

### Требования

- Python 3.11+
- API-ключ OpenPageRank (`OPR_API_KEY`)

### Шаги

1. Клонировать репозиторий.
2. Создать виртуальное окружение и активировать:
   ```bash
   python -m venv venv
   source venv/bin/activate  # или venv\Scripts\activate для Windows
   ```
3. Установить зависимости:
   ```bash
   pip install -r services/traffic_stats/requirements.txt
   ```
4. Создать `.env` в папке `services/traffic_stats/` и задать `OPR_API_KEY`:
   ```
   OPR_API_KEY=ваш_ключ
   ```
5. Запустить сервис (через Docker, как в продакшене):
   ```bash
   uvicorn src.main:app --host 0.0.0.0 --port 8008
   ```

По умолчанию сервер запускается на порту **8008** (пробрасывается на `127.0.0.1:8009`).

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `OPR_API_KEY` | **Обязательный** API-ключ OpenPageRank (Bearer-токен) | (обязательно) |
| `OPR_BASE_URL` | URL эндпоинта OpenPageRank | `https://openpagerank.keywordseverywhere.com/v1/domains/bulk` |
| `OPR_TIMEOUT` | Таймаут запроса к OpenPageRank (секунды) | `30` |
| `STORAGE_SERVICE_URL` | URL внутреннего сервиса `storage` | `http://storage:8007` |

> **Примечание:** в репозитории файл `.env` сервиса пуст. `OPR_API_KEY` должен быть задан (например, через общий `.env` проекта или `docker-compose.yml`).

## Архитектура и логика работы

1. **Приём запроса** — `POST /analyze` принимает список доменов (`domains`).
2. **Нормализация** — каждый домен проходит через `utils.clean_domain`: удаляются протокол (`http://`/`https://`), пути, порты и префикс `www.`. Затем список дедуплицируется (валидатор `clean_and_deduplicate` в `AnalyzeRequest`).
3. **Запрос к OpenPageRank** — `OPRClient.fetch_bulk` разбивает домены на чанки по **100** (лимит API) и отправляет POST-запросы.
4. **Ретраи** — клиент обёрнут декоратором `@retry` из `tenacity`: до **3 попыток** с экспоненциальной задержкой (от 2 до 10 секунд). Повтор происходит только при `httpx.TimeoutException`, `httpx.NetworkError` и `OPRServerError` (5xx). При ошибках 4xx сразу выбрасывается `OPRClientValidationError`.
5. **Сохранение** — `StorageClient.save_task_data` вызывается после получения результата, но **пока заглушен** (только пишет в лог). Реальный запрос к `storage` закомментирован до согласования внутреннего API-контракта.
6. **Ответ клиенту** — возвращается `AnalyzeResponse` со счётчиками (`total_requested`, `successful`, `failed`) и списком результатов.

### Инициализация клиентов

Клиенты `OPRClient` и `StorageClient` создаются **один раз при старте** приложения через `lifespan` в `main.py` и кладутся в `app.state`. Это позволяет переиспользовать их между запросами без повторного создания.

## API

### POST /analyze

Принимает список доменов и возвращает статистику авторитетности.

**Запрос:**
```json
{
  "domains": ["lenta.ru", "ria.ru", "tass.ru"]
}
```

**Ответ:**
```json
{
  "task_id": "uuid",
  "status": "completed",
  "as_of": "2026-09-17",
  "total_requested": 3,
  "successful": 3,
  "failed": 0,
  "results": [
    {
      "domain": "lenta.ru",
      "found": true,
      "open_page_rank": 6.5,
      "rank": 1500,
      "referring_domains": 120000
    }
  ]
}
```

> **Примечание:** поле `found` указывает, нашёл ли OpenPageRank домен. Домены с `found: false` учитываются в счётчике `failed` и не считаются валидными (`is_valid` возвращает `found`).

**Коды ошибок:**
- `502 Bad Gateway` — если `OPRClient` не смог получить данные (после всех ретраев).
- `500 Internal Server Error` — при неожиданных ошибках.

### GET /task/{task_id}

Возвращает статус задачи по `task_id`.

**Не реализован** — всегда возвращает `501 Not Implemented` с сообщением «Task retrieval from storage is not implemented yet». Заглушка для будущей функциональности получения сохранённых результатов из `storage`.

### GET /health

Проверка работоспособности сервиса.

**Ответ:** `{"status": "ok"}`

## Интеграция с другими сервисами

- **Админ-панель** (`index.html` / `app.js`) — вызывает `POST /traffic_stats/analyze` при нажатии кнопки «📊 Измерить» в блоке «Управление списком сайтов». Результаты отображаются в таблице (домен, ранг, Open Page Rank, ссылающиеся домены).
- **`storage`** — планируется сохранение результатов измерений через `StorageClient.save_task_data`, но сейчас это заглушка (только логирование). Настройка `STORAGE_SERVICE_URL` указывает на внутренний адрес `storage`.

## Беклог (дальнейшие улучшения)

### Реализация заглушек

- Реализовать реальное сохранение результатов в `storage` через `StorageClient.save_task_data` (сейчас только лог). Требуется согласовать внутренний API-контракт со `storage`.
- Реализовать эндпоинт `GET /task/{task_id}` для получения сохранённых результатов (сейчас возвращает 501).

### Известные проблемы

- В `main.py` используется `settings.PORT` в блоке `if __name__ == "__main__"`, но поле `PORT` **не определено** в `config.py`. При запуске через `python -m` это приведёт к ошибке. В продакшене сервис запускается через `uvicorn` с жёстко заданным портом в `Dockerfile`, поэтому блок не выполняется.

### Функциональность

- Добавить кэширование результатов (чтобы не запрашивать OpenPageRank повторно для тех же доменов в течение короткого периода).
- Поддержка `include_history` для получения исторических данных (сейчас всегда `False`).
- Асинхронное выполнение для больших списков доменов (сейчас запрос синхронный в рамках одного вызова).

### Безопасность

- Добавить авторизацию через JWT (проверка токена через `user_manager`).
- Ограничение количества запросов (rate limiting) для защиты от перегрузки внешнего API.

## Используемые технологии

- **FastAPI** — веб-фреймворк
- **httpx** — асинхронный HTTP-клиент для запросов к OpenPageRank
- **tenacity** — ретраи с экспоненциальной задержкой
- **Pydantic / pydantic-settings** — валидация данных и конфигурация
- **uvicorn** — ASGI-сервер
