# Analyzer — сервис кластеризации и детекции дрифта

Сервис загружает векторы (Parquet-файлы) пользователя за указанные периоды **через API сервиса `storage`**, выполняет кластеризацию с использованием UMAP и HDBSCAN, вычисляет дрейф тем (Wasserstein Distance) и возвращает аналитический отчёт в JSON. Используется для выявления изменений в тематике новостных потоков.

> **Важно:** начиная с Этапа 10 (фича «Мульти-модельность»), сервис запрашивает из `storage` только те векторы, которые соответствуют **активной модели пользователя** (`model_slug`). Это предотвращает смешивание векторов разной размерности (например, 768-мерных от локальной E5 и 256-мерных от Яндекс API), которое привело бы к ошибке при кластеризации.

## Установка и запуск локально

### Требования

- Python 3.11+
- Запущенный сервис `storage` (для получения векторов через API)
- Наличие векторов в `storage` (создаются сервисом `embedder`)

### Шаги

1. Клонировать репозиторий.
2. Создать виртуальное окружение и активировать:
   ```bash
   python -m venv venv
   source venv/bin/activate  # или venv\Scripts\activate для Windows
   ```
3. Установить зависимости:
   ```bash
   pip install -r services/analyzer/requirements.txt
   ```
4. Запустить сервис:
   ```bash
   python -m services.analyzer.src.main
   ```

По умолчанию сервер запускается на порту **8004**.

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `VECTORS_ROOT` | Корневая папка с Parquet-файлами (наследие, актуально для локальных тестов) | `./data/vectors` |
| `CLUSTERS_ROOT` | Папка для сохранения промежуточных результатов | `./data/clusters` |
| `UMAP_N_COMPONENTS` | Размерность после UMAP | `5` |
| `HDBSCAN_MIN_CLUSTER_SIZE` | Минимальный размер кластера | `5` |
| `PORT` | Порт для FastAPI | `8004` |
| `STORAGE_URL` | **URL сервиса `storage`** для получения векторов через API | `http://storage:8007` |

## API

### POST /analyze

Принимает `user_id` и количество недель для сравнения, возвращает результаты кластеризации и дрифта.

**Запрос:**
```json
{
  "user_id": "admin",
  "weeks": 2
}
```

**Ответ:**
```json
{
  "drift_score": 0.35,
  "shifted_topics": [
    {
      "old_terms": ["ИИ", "этика"],
      "new_terms": ["ИИ", "агенты"]
    }
  ],
  "cluster_details": {
    "current_week": {
      "clusters": {
        "cluster_0": {
          "size": 10,
          "terms": ["ИИ", "роботы"]
        }
      },
      "total_samples": 10
    },
    "previous_week": {
      "clusters": {
        "cluster_0": {
          "size": 8,
          "terms": ["ИИ", "этика"]
        }
      },
      "total_samples": 8
    }
  }
}
```

## Логика работы

1. **Определение активной модели** — сервис запрашивает настройки пользователя через `GET /settings/{user_id}` в `storage` и получает поле `active_model_slug`. Это необходимо, чтобы анализировать только векторы той модели, которая сейчас активна у пользователя.
2. **Загрузка векторов** — сервис запрашивает список векторов пользователя через `GET /list?user_id={user_id}&file_type=vectors&model_slug={active_model_slug}` в `storage`. Затем скачивает каждый Parquet-файл за указанные периоды (текущая и предыдущая недели) через `GET /download/{file_id}`.
3. **Кластеризация** — векторы стандартизируются, затем размерность снижается с помощью UMAP, после чего применяется HDBSCAN для выделения кластеров. Для каждого кластера извлекаются топ-термины (на основе частоты слов в текстах).
4. **Дрифт** — вычисляется Wasserstein Distance между распределениями векторов текущей и предыдущей недели. Чем выше значение, тем сильнее изменилась тематическая структура.
5. **Сместившиеся темы** — сопоставляются кластеры разных недель и фиксируются изменения в терминах.

> **Изоляция по модели:** если пользователь сменит активную модель, `analyzer` автоматически начнёт анализировать только векторы новой модели. Старые векторы другой модели будут проигнорированы, что предотвращает ошибку несовпадения размерностей.

## Интеграция с другими сервисами

- **Вход:** векторы от `embedder` (хранятся в `storage`, получаются через API с фильтром по `model_slug`).
- **Настройки пользователя:** получаются из `storage` (поле `active_model_slug`).
- **Выход:** JSON, который может быть передан в `reporter` для генерации HTML-отчёта.

## Беклог (дальнейшие улучшения)

### Алгоритмы

- Улучшить сопоставление кластеров для более точного поиска сместившихся тем (например, на основе центроидов или пересечения терминов).
- Внедрить многомерную версию Earth Mover's Distance для более точного дрифта.

### Производительность

- Кэшировать результаты кластеризации (например, для одинаковых периодов).
- Оптимизировать UMAP/HDBSCAN для больших объёмов данных (использовать `umap-learn` с `n_jobs`).

### Архитектура

- Добавить поддержку произвольных дат (параметры `start_date` и `end_date` в запросе).

### Безопасность

- Добавить JWT-авторизацию (проверка токена через `user_manager`).

## Используемые технологии

- **FastAPI** – веб-фреймворк
- **numpy / pandas** – работа с данными
- **pyarrow** – чтение Parquet-файлов
- **scikit-learn** – стандартизация
- **umap-learn** – снижение размерности
- **hdbscan** – кластеризация
- **scipy** – расчёт Wasserstein Distance
- **httpx** – асинхронные HTTP-запросы к `storage`
- **Pydantic** – валидация данных
