# Reporter — сервис генерации HTML-отчётов

Сервис принимает результаты анализа (JSON от `analyzer`), строит интерактивные графики с помощью `plotly` и сохраняет HTML-отчёт **в сервис `storage`** через API. Отчёт содержит визуализацию дрифта, кластеров и сместившихся тем. Предусмотрена заглушка для будущей интеграции с YandexGPT.

> **Важно:** начиная с Этапа 10 (фича «Мульти-модельность»), данные, которые `reporter` получает от `analyzer`, уже отфильтрованы по активной модели пользователя. Это означает, что отчёты строятся только по релевантным векторам, без смешивания моделей разной размерности.

## Установка и запуск локально

### Требования

- Python 3.11+
- Результат от `analyzer` (JSON) для передачи в запросе
- Запущенный сервис `storage` (для сохранения отчётов)

### Шаги

1. Клонировать репозиторий.
2. Создать виртуальное окружение и активировать:
   ```bash
   python -m venv venv
   source venv/bin/activate  # или venv\Scripts\activate для Windows
   ```
3. Установить зависимости:
   ```bash
   pip install -r services/reporter/requirements.txt
   ```
4. Запустить сервис:
   ```bash
   python -m services.reporter.src.main
   ```

По умолчанию сервер запускается на порту **8005**.

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `STORAGE_URL` | **URL сервиса `storage`** для сохранения отчётов через API | `http://storage:8007` |
| `REPORTS_ROOT` | Корневая папка для локального сохранения отчётов (используется устаревшим эндпоинтом `/reports/{user_id}/{filename}`) <!-- проверить актуальность --> | `./data/reports` |
| `PLOTLY_TEMPLATE` | Шаблон оформления графиков | `plotly_white` |
| `PORT` | Порт для FastAPI | `8005` |

## API

### POST /generate

Принимает результат анализа (`analysis_result`) и `user_id`, генерирует HTML-отчёт, сохраняет его в `storage` и возвращает ссылку на него.

**Запрос:**
```json
{
  "user_id": "admin",
  "analysis_result": {
    "drift_score": 0.75,
    "shifted_topics": [
      {
        "old_terms": ["ИИ", "этика"],
        "new_terms": ["ИИ", "агенты"]
      }
    ],
    "cluster_details": {
      "current_week": {
        "clusters": {
          "cluster_0": {
            "size": 10,
            "terms": ["ИИ", "роботы"]
          }
        },
        "total_samples": 10
      },
      "previous_week": {
        "clusters": {
          "cluster_0": {
            "size": 8,
            "terms": ["ИИ", "этика"]
          }
        },
        "total_samples": 8
      }
    }
  }
}
```

**Ответ:**
```json
{
  "status": "ok",
  "report_url": "/reports/uuid-файла-в-storage",
  "text_summary": "Заглушка: текстовое описание трендов будет добавлено позже."
}
```

> **Примечание:** `report_url` имеет формат `/reports/{file_id}`, где `file_id` — идентификатор файла в `storage`. Этот путь проксируется через `nginx` на `storage` для скачивания отчёта.

### GET /reports/{user_id}/{filename}

Отдаёт HTML-файл отчёта из локальной папки `REPORTS_ROOT`. **Этот эндпоинт устарел**, так как отчёты сохраняются в `storage`, а не в локальную папку. Он может использоваться для доступа к старым отчётам, сохранённым до перехода на `storage`. <!-- проверить: используется ли этот эндпоинт сейчас -->

### GET /health

Проверка работоспособности сервиса.

## Логика работы

1. **Приём данных** — сервис получает JSON от `analyzer`. Данные уже отфильтрованы по активной модели пользователя (Этап 10), что гарантирует корректность визуализации.
2. **Генерация графиков** — строятся:
   - Спидометр дрифта (показывает значение `drift_score` в процентах).
   - Визуализация кластеров (сейчас заглушка, в будущем — 2D-проекция UMAP).
   - Таблица сместившихся тем — отображает старые и новые термины для каждого сдвига.
3. **Формирование HTML** — графики встраиваются в HTML-страницу с использованием `plotly`.
4. **Сохранение в `storage`** — HTML-файл сохраняется в `storage` через `POST /upload` с типом `reports`. В метаданных указываются `drift_score` и количество сместившихся тем.
5. **Возврат ссылки** — клиент получает `report_url` в формате `/reports/{file_id}`, который проксируется через `nginx` на `storage` для скачивания отчёта.

## Интеграция с другими сервисами

- **Вход:** JSON от `analyzer` (передаётся в теле запроса). Данные уже отфильтрованы по активной модели.
- **`storage`:** хранит отчёты (`file_type=reports`) и обеспечивает их отображение в админ-панели и доступ по ссылке `/reports/{file_id}`.
- **Выход:** `report_url` и `text_summary` (заглушка для LLM).
